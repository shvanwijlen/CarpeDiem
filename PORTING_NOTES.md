# Porting notes: CarpeDiem (ESP32-S3 Arduino) → CarpeDiem (Raspberry Pi / Python)

Everything below is a deliberate change from the original sketches
(`CarpeDiem_v4_5_20260830c.ino` and `ais_nearby_vessels_7.ino`), with the
reasoning, so you can audit and revert anything you disagree with.

## Real bugs fixed

- **Modbus register label mismatch**: `regs[]` had a register labeled
  `"Battery Voltage (V)"`, but `DisplayInfo[]`'s field was
  `"Battery0 Voltage (V)"`. `UpdateDisplayTable()` does an exact string
  match, so that reading was silently dropped every cycle. Fixed by
  renaming the register's label to match (`modbus_client.py`).
- **MQTT values with nowhere to land**: `callback()` had real, correct
  code paths for `battery/278/Dc/1/*` (Battery1 voltage/current/power) and
  `system/0/Dc/Battery/Power` (Battery Power), but `DisplayInfo[]` had no
  matching fields for any of them - same silent-drop issue. Fixed by
  adding the missing fields to `display_data.py` rather than just
  discarding data that was already being collected.
- **Duplicate/dead `else if` branch**: `system/0/Dc/System/Current` had
  two identical branches in the callback's if/else chain; the second was
  unreachable. Removed.
- **Debug-only 10s freeze on unmatched MQTT topics**: the original did
  `delay(10000)` on the "not yet covered" path - harmless-ish on a
  single-threaded Arduino loop, but pointless (and would have blocked
  everything) if ported as-is to a normal service. Removed; it just logs
  now.

## Removed entirely

- **The whole SD-card subsystem** (~250 lines: card-detect, disk-usage%
  cleanup, manual rotate/retention, custom SPI driver). The Pi's normal
  filesystem + Python's `logging.handlers.RotatingFileHandler` covers all
  of it - see `logging_setup.py`.
- **WiFi connect logic**. The Pi's network is managed by the OS, not this
  app.
- **NTP-sync-before-connecting dance** from `ais_nearby_vessels_7.ino`
  (the ESP32 needed a sane clock before its TLS stack would handshake to
  AISstream.io). The Pi should just be kept NTP-synced at the OS level;
  nothing app-specific needed.
- **`splitFieldsKeepEmpty()`**: existed only to work around `strtok()`
  silently collapsing consecutive delimiters in C. Python's
  `line.split(",")` already preserves empty fields.
- **Manual line buffering** (`lineBuf`/`lineLen`/`LINE_BUF_LEN`, char by
  char). `asyncio.StreamReader.readline()` does this correctly with no
  fixed-size limit to overrun.
- **Fixed-size vessel array + oldest-slot eviction** (`MAX_VESSELS=50` +
  manual "find free slot, else evict oldest"). A plain `dict` keyed by
  MMSI does the same job with no size cap or bookkeeping needed - still
  pruned on the same 10-minute staleness timeout.

## Behaviour changes

- **DoShow logging**: the original printed the full display table on
  *every* pass of `loop()` - as fast as possible in `DoFake` mode, which
  the sketch's own TODO comment flags as confusing ("klopt het dat hij in
  DoFake mode maar 1x per seconde data langsloopt?"). It's now a plain
  5-second timer (`SHOW_INTERVAL_SECONDS` in `main.py`), independent of
  `DoFake`.
- **Concurrency model**: one `asyncio` task per subsystem instead of a
  single polling loop with a hand-rolled "reconnect only every 5 min"
  gate. See README's Architecture note.

## Vessel names: VesselAPI → AISstream.io

The original CarpeDiem sketch's TODO mentioned a "VesselAPI" REST lookup,
but flagged its own free tier (150 lookups / 90 days) as impractical for
continuous use. `ais_nearby_vessels_7.ino` had already moved on to
**AISstream.io** - a free WebSocket feed with no such quota, subscribed to
a bounding box around your own position and filtered to `ShipStaticData`
messages. The Python port uses that (`ais/aisstream_client.py`); there's
no VesselAPI code left anywhere.

## New: the AIS range/bold filter (was a TODO, now implemented)

The original sketch had this as an unimplemented TODO:

> AIS details: limiteren tot alles binnen 1km, tenzij sneller varend dan
> 10km en dan max 2km >> en in bold tonen

`vessel_tracker.py`'s `nearby()` now implements this: pass
`apply_range_filter=True` to only get vessels within 1km (or 2km if your
own speed exceeds 10 km/h), and every result carries a `close: bool` a
future renderer can use to bold/highlight it. Off by default - the filter
is opt-in per call.

## Verified against a real decoder

`ais/decoder.py`'s bit-level AIS decoding (position reports for types
1/2/3/18/19, names for types 5 and 24A, including the 2-fragment
reassembly for type 5) was cross-checked against `pyais` - an independent,
widely-used AIS decoding library - using both a known real-world test
sentence and several synthetic ones generated by `pyais`'s own encoder.
All fields matched exactly (MMSI, lat/lon, speed, course, vessel name).
`pyais` itself isn't a dependency of the shipped app; it was only used
as a one-off correctness check during development.

## Not yet wired up / needs your input

- **Modbus**: targets `pymodbus>=3.8`'s `device_id=` kwarg (pymodbus
  renamed this from `slave=` in 3.8, and from `ModbusSlaveContext` to
  `ModbusDeviceContext` server-side in a later 3.x release still mid-
  deprecation as of writing). The client code's kwarg name was verified
  directly against the installed library's function signature, but a
  full round-trip read hasn't been tested against your actual Cerbo GX -
  worth watching closely on first real run.
- **RTC / LED matrix**: both off by default (`CARPEDIEM_USE_RTC` /
  `CARPEDIEM_USE_MATRIX`), since you said to make them optional rather
  than assume you're keeping that hardware wired to the Pi.
- **Display renderer**: doesn't exist yet - this port is the data layer.
  `display_data.snapshot()` and `AisService.nearby_vessels()` are the two
  read APIs a renderer would use.
